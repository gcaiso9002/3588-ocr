# 07 — 轻量版（Tk）打包成「点开就能用」的绿色软件

把 Windows 端的截图取字工具打成一个**单文件 exe**：双击就运行，不需要装 Python、
不需要 `pip install`、不写注册表、卸载就是删一个文件。

> ⚠️ **这是轻量版（v1.0.0，16.8 MB）**。
> v1.1.0 起主推 **Electron 版**（~100 MB），界面重做并补了完整设置界面，
> 打包方式见 [08-Electron桌面端.md](08-Electron桌面端.md)。
> 本文讲的是 Tk 版的打包。
>
> 这一步只是**打包**，不改变任何识别逻辑。识别始终在板子的 NPU 上跑，
> exe 只是把「截图 → 发 HTTP → 显示文字」这段客户端代码封起来。

## 2. 「绿色」体现在哪

| 绿色要素 | 实现 |
|---|---|
| 免安装 | 单文件 exe，双击即用，不写 `Program Files`，不建快捷方式 |
| 不碰注册表 | 没有 `HKCU\Run` 自启项，没有 `HKCR` 关联，没有 COM/服务注册 |
| 配置不污染目录 | 配置写 `%APPDATA%\3588-ocr\npu_ocr_gui_config.json`，**不在 exe 旁边** |
| 卸载 = 删文件 | 删掉 exe，再顺手删 `%APPDATA%\3588-ocr` 目录即可，零残留 |
| 零网络依赖 | 客户端只跟局域网里的板子通信，不连任何云服务 |

关键的一条是**配置路径**。冻结后的 exe 运行时 `sys.executable` 指向 PyInstaller 的
临时解包目录（`%TEMP%\_MEIxxxxxx`），如果还把配置写在 exe 旁边，
下次启动就找不到上次的配置了。所以代码里做了分支：

```python
if getattr(sys, "frozen", False):
    CONFIG_DIR = os.path.join(os.environ["APPDATA"], "3588-ocr")
else:
    CONFIG_DIR = HERE          # 源码运行时仍然用脚本旁边的 json，方便开发
```

## 3. 开箱即用：自动找到板子

板子的 IP 会变（换网口、DHCP 续租）。如果 exe 把地址写死，用户就得每次去
「设置」里改地址 —— 这就不叫绿色软件了。

所以 exe 启动后会**自己找板子**，顺序是：

1. **配置文件里的地址** —— 先试 `%APPDATA%` 里的 `server`；
2. **内置候选地址** —— `server_candidates`（默认含板子的另一个网口 `192.168.31.40`）；
3. **扫本地 /24** —— 取本机出站路由 IP（UDP `connect` 到 `8.8.8.8`，不发包），
   然后用 96 个线程并发探测 `x.x.x.1 ~ x.x.x.254` 的 8766 端口。

第 3 步的并发探测在千兆网线上 **约 1~2 秒** 扫完整个 /24（每个 host 超时 0.35 s）。
找到后自动把新地址写回配置，下次启动就直接命中，不用再扫。

### 命中判定：不能只看端口通不通

`/health` 返回体里必须含 `det` 字段才算命中：

```python
return data if data.get("ok") and "det" in data else None
```

因为局域网里别的机器也可能开着 8766 端口（比如别的服务）。`det` 是
`npu-ocr.service` 独有的字段，能避免误连到不相干的服务上。

### 找不到板子时

弹出提示「没找到板子服务」，告诉你确认板子已开机、网线已插，然后去设置里填地址。
不会静默失败。

## 4. 命令行参数

```
3588-ocr.exe [--server http://<ip>:8766] [--log <日志文件>] [--save-dir <目录>]
```

| 参数 | 作用 |
|---|---|
| `--server URL` | 启动时指定板子地址（会写进配置持久化） |
| `--log FILE` | 把运行日志写到文件，排障用 |
| `--save-dir DIR` | 每次识别额外存一张裁剪图到目录 |

## 5. 自己构建

**必须在干净的虚拟环境里构建。** 直接在 Anaconda base 环境跑 PyInstaller 会失败：

```
AttributeError: 'PosixPath' object has no attribute 'startswith'
```

原因是老版本 `pathlib` backport 跟新版 PyInstaller 不兼容（不是 PyInstaller 的 bug，
是环境脏）。做法：

```powershell
cd desktop
python -m venv ..\buildenv
& "..\buildenv\Scripts\python.exe" -m pip install pyinstaller pillow pystray pywin32
& "..\buildenv\Scripts\python.exe" make_exe.py
```

产物在 `desktop\dist\3588-ocr.exe`。

### 构建过程中的坑

1. **`dist\3588-ocr.exe` 正在运行时重新构建会失败**：
   `PermissionError: [WinError 5]`。先在任务管理器里结束掉旧进程再构建。
2. **`pystray._win32_api` 在新版 pystray 里已经不存在**。
   写在 `--hidden-import` 里会报 `Hidden import not found` 并让构建失败。
   正确的隐藏导入是 `pystray._win32`。
3. **排除掉 `numpy`**。客户端只是转发图片和解析 JSON，用不到 numpy；
   排掉之后 exe 小了一圈。
4. 图标由 `make_icon.py` 用 Pillow 现画（蓝色圆角方块 + 文档 + 放大镜），
   仓库里的 `3588-ocr.ico` / `3588-ocr.png` 就是它生成的。

## 6. 端到端自检

打包完不要只看着 exe 大小就交付，仓库里带了两个真跑一遍的测试：

```powershell
& "..\buildenv\Scripts\python.exe" test_exe.py           # 真的按 Ctrl+1 框选并读剪贴板
& "..\buildenv\Scripts\python.exe" test_exe_discover.py  # 把配置指向死地址，验证自动发现
```

`test_exe.py` 做的事：

1. 起一个置顶的 Tk 窗口，上面写着 `识别测试 67890` / `Hello 12345 ABCdef`；
2. 起 exe，等 8 秒；
3. 用 `keybd_event` 模拟 **Ctrl+1**；
4. 用 `SetCursorPos` + `mouse_event` 真的拖一个框；
5. 从剪贴板读回文字，判断 `12345` / `ABCdef` / `识别测试` 是否都在。

实测结果：

```
RESULT    : PASS      # 识别测试 67890 / 12345 / Hello / ABCdef
```

耗时 **0.67 ~ 0.70 s**（含一次完整的 HTTP 请求 + 板子上 NPU 推理）。

> ⚠️ **测试脚本自己也必须设 DPI aware**
> （`SetProcessDpiAwarenessContext(-4)`）。
> 否则 `SetCursorPos` 的坐标会被系统虚拟化，量出来的选区会差 1.5 倍，
> 第一次跑会误判成 app 有 bug —— 其实是驱动脚本的问题。

## 7. 已知限制

1. **只支持 Windows**。exe 用到了 `ctypes` 的 Win32 API（全局热键、剪贴板、
   托盘），在 macOS / Linux 上跑不了。跨平台要用别的打包与热键方案。
2. **必须能访问到板子**。板子关机或网线拔了，exe 会提示找不到服务
   （已内置 `/24` 扫描自动重连，板子换了 IP 也能找回）。
3. **没有代码签名**。Windows SmartScreen 第一次运行会弹「Windows 已保护你的电脑」，
   点「更多信息 → 仍要运行」即可。买代码签名证书能去掉这个提示，但没必要为个人工具花这钱。
4. **exe 体积 16.8 MB**。主要来自 Python 运行时 + Pillow + pywin32 + pystray。
   识别全在板子上，所以这里没有塞模型。
