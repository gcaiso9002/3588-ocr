# 05 · 桌面取字工具（Windows，Electron 版）

仿天若 OCR / 白描电脑版：**全局快捷键 → 框选 → 出字 → 进剪贴板**。

识别跑在 RK3588 板子的 NPU 上，电脑这边只负责截图、选区、取词、复制/粘贴。
客户端用 **Electron** 写，界面是自绘的圆角卡片 + 侧边栏设置界面。

> v1.2.0 起**只有这一个桌面客户端**。之前的 Tk 版（v1.0.0，16.8 MB）
> 因为界面是系统原生控件、观感太差，已经整个删除，不再维护。

> v1.2.1 修了一个**选区遮罩卡死**的 bug（连按热键会并发抓屏，漏出关不掉的
> 野窗口，十字光标卡在屏幕上、Esc 也按不掉）。详见 [§8 修过的 Bug](#8-修过的-bug)。

## 1. 三个界面

| 界面 | 说明 |
|---|---|
| **结果面板** | 圆角悬浮卡片，顶部标题栏（行数 · 耗时），中间可编辑文本区，底部操作条 |

### 什么会触发截图，什么不会（v1.2.6）

**原则：只有你主动要，才会截图。**

| 操作 | 会不会截图 |
|---|---|
| 按 **Ctrl+1** | ✅ 会（这就是主入口） |
| 点悬浮工具条上那个蓝色圆形按钮 | ✅ 会（按钮上画的就是截图图标） |
| 托盘右键菜单 →「截图取字」 | ✅ 会（菜单项写着） |
| **双击 exe**（程序已在跑） | ❌ **不会**，只会把设置窗口亮出来 |
| **单击托盘图标** | ❌ **不会**，只弹右键菜单 |
| 开机自启 / 后台常驻 | ❌ 不会 |

> 以前双击 exe 会直接开始截图 —— 因为 `second-instance` 的处理里写的是
> 「有设置窗口就显示，否则 `startCapture()`」。用户的本意只是「我想打开它」，
> 结果屏幕上突然压上一层选框，很吓人。现在改成只打开设置窗口。
>
> 单击托盘图标以前也是直接截图，现在按 Windows 惯例改成弹菜单。

### 版本号标在四个地方（v1.2.5）

以前关于页的版本号是**写死在 HTML 里的**（`1.1.0`），从来没被 JS 填过，
所以连着好几个版本都显示 1.1.0，根本分不清自己在用哪一版。现在：

| 位置 | 显示 |
|---|---|
| **exe 文件名** | `3588-ocr-1.2.5.exe`（`artifactName` 用 `${version}`） |
| **设置窗口标题栏** | `3588-ocr` + 蓝色 `v1.2.5` 徽标 + `设置` |
| **设置 → 关于** | `版本 1.2.5 · Electron 客户端` |
| **托盘** | 悬停提示与右键菜单第一行都是 `3588-ocr v1.2.5` |

版本号只在 `package.json` 里写一处，主进程 `APP_VERSION` 读它，
渲染层通过 `window.api.version()` 拿，**界面上没有任何硬编码的版本字符串**。

### 结果面板要不要弹，可以选

**设置 → 基本设置 → 识别结果显示**，三档：

| 选项 | 行为 |
|---|---|
| **弹出结果面板，并一直保留** | 识别完弹出面板，可以改文字、复制、翻译，不自动关 |
| **弹出结果面板，复制后自动关闭** | 弹出面板，3 秒后自动关掉；期间你点了复制/改文字，就不关了 |
| **不弹出，只把文字放进剪贴板** | 屏幕上什么都不出，文字直接进剪贴板 —— 适合「取完字接着干活」 |

## 3. 关键实现

### 3.1 每块屏一个遮罩窗口，而不是一个大窗口

Electron 的 `screen` API 返回的是**每块屏各自的 DIP**（主屏 3840×2160@150% → 2560×1440 DIP，
副屏 1080×1920@100% → 1080×1920 DIP）。

如果做一个横跨虚拟桌面的大窗口，Windows 只会给这个窗口**一个 DPI 上下文**，
副屏那部分就会整体缩放错位，选区框和实际内容对不上。

所以本实现是**每块屏开一个遮罩窗口**，窗口尺寸正好等于该屏的 DIP 尺寸：

```js
new BrowserWindow({
  x: s.display.bounds.x, y: s.display.bounds.y,
  width: s.display.bounds.width, height: s.display.bounds.height,
  frame: false, transparent: true, alwaysOnTop: true, skipTaskbar: true,
});
```

每块屏内部都是 1:1 精确的，代价是**选区不能跨屏**（在哪块屏按下就只在那块屏里选）。

### 3.2 裁剪在渲染层用 canvas 做，不在主进程做

遮罩窗口里的 `<canvas>` 后端缓冲是**物理像素**（`bounds.width * scaleFactor`），
显示尺寸是 DIP。选区确定后直接从画布上按 1:1 裁出来：

```js
const s = state.scaleFactor;
const sx = Math.round(r.x * s), sy = Math.round(r.y * s);
const sw = Math.round(r.w * s), sh = Math.round(r.h * s);
ctx.drawImage(shot, sx, sy, sw, sh, 0, 0, sw, sh);
```

好处：主进程完全不用关心 DPI 换算，裁剪出来的一定是**用户在屏幕上框的那几个物理像素**。

实测校准：鼠标拖 `(458,458)→(1300,834)`（物理），应用记录
`{x:305, y:305, w:561, h:251}`（DIP），×1.5 还原 = `(458,458,842,377)`，**像素级一致**。

### 3.3 抓屏要 1:1，每块屏单独取一次

`desktopCapturer.getSources()` 的 `thumbnailSize` 对所有屏是同一个值，
给一个「最大屏」的尺寸会让别的屏被等比缩放。所以**每块屏单独调一次**：

```js
const pw = Math.round(d.bounds.width * d.scaleFactor);
const sources = await desktopCapturer.getSources({
  types: ['screen'], thumbnailSize: { width: pw, height: ph },
});
```

再按 `source.display_id` 匹配回对应的 display。

### 3.4 Windows 上必须注册屏幕捕获的 handler

不注册的话 `desktopCapturer` 很可能拿到**黑屏**：

```js
session.defaultSession.setDisplayMediaRequestHandler((request, callback) => {
  desktopCapturer.getSources({ types: ['screen'] }).then((sources) => {
    callback({ video: sources[0] });
  });
}, { useSystemPicker: false });
```

### 3.5 全局热键

Electron 的 `globalShortcut` 直接可用，不用自己 ctypes 调 `RegisterHotKey`：

```js
globalShortcut.register('CommandOrControl+1', onHotkey);
```

`ctrl+1` → `CommandOrControl+1`（`CommandOrControl` 在 Windows 上就是 Ctrl）。

**热键被占用时自动降级**：注册失败就按修饰键不变、换一批键名（`2 3 4 … q w e r …`）
再试，并把**实际生效的键**明确告诉用户（弹窗 + 托盘菜单 + 日志）。
配置里的原键不会被改写，用户随时能在「设置 → 快捷键」里改回来。

设置界面里的快捷键输入框支持**直接按下组合键录制**（点一下输入框，按 Ctrl+Shift+A，松开即记录）。

### 3.6 模拟粘贴：一次 PowerShell 调用

要把焦点还给截图前的窗口，需要 Win32 的 `SetForegroundWindow` + 模拟按键。
不引原生模块（免去编译和 ABI 问题），用一段 PowerShell：

```powershell
# native/focus.ps1
#   -Mode capture        打印当前前台窗口句柄
#   -Mode paste -Hwnd N 把焦点还给 N 号窗口并发送 Ctrl+V
```

`SetForegroundWindow` 有「前台锁」限制，所以脚本里用 `AttachThreadInput`
挂到前台线程再调用，否则大概率失败。粘贴前先把识别结果写进剪贴板，再发 Ctrl+V。

### 3.7 配置与「绿色」

- 配置：`%APPDATA%\3588-ocr\config.json`
- 日志：`%APPDATA%\3588-ocr\3588-ocr.log`
- 不写注册表、不写 `Program Files`、卸载 = 删 exe + 删 `%APPDATA%\3588-ocr`

## 4. 选区交互（天若式）

按 **Ctrl+1** 之后：

```
                 ┌─────────────────────────────────────┐
   Ctrl+1  ───► │ 抓屏（双屏并行，约 0.9~1.2 秒）        │
                 └──────────────┬──────────────────────┘
                                ▼
                 ┌─────────────────────────────────────┐
                 │ 选区界面：十字光标 + 放大镜 + 尺寸标签  │
                 └──────────────┬──────────────────────┘
                                │
      ┌─────────────┬───────────┼────────────┬──────────────┐
      ▼             ▼           ▼            ▼              ▼
  拖动+松开      2 秒内又按    2 秒没动静    按 Esc        鼠标右键
  → 识别出字    一次热键      → 自动撤掉    → 取消         → 取消
                 → 重新抓一次   遮罩，回到
                 （作废上一次）  等下一次
```

### 空闲自动取消（v1.2.3）

选区界面弹出来之后，如果**一直没动静**（鼠标没动、没按键），
默认 **2 秒**后自动把遮罩撤掉，屏幕恢复正常，程序回到「等下一次热键」的状态——
不会再有一块遮罩一直盖在屏幕上。

- **任何一点动作都重新计时**：挪一下鼠标、点一下、按任意键。
- **拖拽过程中不会被打断**：拖拽时渲染层每 400ms 报一次活动，保住计时器。
- 时间可调：**设置 → 识别 → 选区无操作自动取消**（0 ~ 60 秒，填 0 = 不自动取消）。

### 抓屏途中再按热键 = 最新的赢（v1.2.3）

抓屏要将近 1 秒，这期间再按一次热键，**不是忽略**：
这一次抓完的结果会**直接作废**，立刻重新抓一次。
所以「按一下就开始截图；嫌慢再按一下」这个手感是成立的——
最后按的那次一定对应你真正想要的那张画面。

> 热键加了 250ms 防抖：按住 Ctrl+1 不放时系统会连发，防抖保证只认「人按了一下」。

## 5. 自己构建

```powershell
cd desktop/electron
npm install
npm start          # 开发模式
npm run dist       # 产出 dist\3588-ocr.exe（免安装单文件）
```

打包用 `electron-builder` 的 **portable** 目标，产出单个 exe。

### 踩过的坑

1. **必须 `npm run dist` 而不是手敲 electron-builder**，否则 `files` 过滤会漏。
2. **下载 electron 二进制要配镜像**，国内直连 GitHub 经常断：

   ```powershell
   $env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
   $env:ELECTRON_BUILDER_BINARIES_MIRROR = "https://npmmirror.com/mirrors/electron-builder-binaries/"
   ```

3. **透明窗口的 `ready-to-show` 不一定触发**，工具条用这个事件显示会一直不出现。
   统一改成 `webContents.once('did-finish-load', () => win.show())`。
4. **窗口建了不 `show()` 就等于没有**——遮罩层踩过一次，选区完全无响应。
5. `web-contents-created` 里挂 `console-message` 转发行内日志，排查渲染层问题非常好用。
6. **JavaScript 没有 printf 风格的 `%` 占位符！**

   ```js
   // ❌ 这是 Python 写法，在 JS 里会拼出 "http://NaN.NaN.NaN.5:8766"
   'http://%s.%s.%s.%d:%d' % (a, b, c, i, port)
   // ✅ 必须用模板字符串
   `http://${a}.${b}.${c}.${i}:${port}`
   ```

   这个坑让「自动扫描网段找板子」**静默失效**：所有 URL 都是非法的，
   扫完 254 个地址耗时 28ms 却一个没命中，日志里只有一句「没找到」。
   教训：扫网段这种「失败了也不报错」的功能，必须**用假地址测一次**才靠谱。
7. **取本机 IP 不能靠枚举网卡**——机器上有虚拟网卡（VMware / Hyper-V / WSL），
   枚举出来的第一个 IPv4 往往是虚拟网段的，扫错地方。
   要用 **UDP connect 让系统按路由表选源地址**（不发包）：

   ```js
   const sock = dgram.createSocket('udp4');
   sock.connect(80, '8.8.8.8', () => resolve(sock.address().address));
   ```

8. **配置文件带 BOM 会让 `JSON.parse` 直接抛异常**，应用静默退回默认值
   （Windows PowerShell 5.1 的 `Set-Content -Encoding UTF8` 就会写 BOM）。
   读的时候要 `.replace(/^\uFEFF/, '')`。
9. **electron-builder 打包时解 winCodeSign 会失败**：7-Zip 要给两个 macOS 的
   `.dylib` 建符号链接，Windows 没那个权限就报
   `Cannot create symbolic link : 客户端没有所需的特权`。
   解法：自己把 `winCodeSign-2.6.0.7z` 用**不带 `-snld`** 的 7za 解到
   `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0\`，
   符号链接降级成普通文件（Windows 用不到 macOS 的 dylib），
   electron-builder 就会直接用缓存，不再下载解压。
10. **图标要自己画 + 每个窗口都设 `icon`**：不设的话窗口会显示 Electron 默认图标，
    托盘图标另外做一份 32px 的简化版，小尺寸下才认得出。

## 6. 端到端自检

### 6.0 无 GUI 自检（默认跑这个，不占桌面）

```powershell
node test_capture_concurrency.js
```

用假的 `electron` 模块加载**真实的 `main.js`**，在毫秒级反复压测
「抓屏期间重复触发热键」这条并发路径。**全程不创建任何窗口、不弹窗、不抢桌面**，
跑完只要半秒。

断言 16 项：并发被拦下、遮罩窗口数恒等于屏幕数、没有野窗口、
系统级 Esc 能关干净、连按 20 次也不多出窗口……

> 这个 bug 是**并发**问题，用假的 Electron 做无头验证比带界面的自检更强：
> 更快、更可重复、能断言窗口的完整生命周期，而且不会打断你手上的活。
> `main.js` 末尾为此开了一个测试口（`module.exports`），正常运行时没人用。

拿旧版本源码跑同一套断言，可以直接看出修复前后的差别：

```powershell

```


### 6.1 抓屏延迟基准（也不开窗口）

```powershell
npx electron bench_capture.js
```

量「串行抓两块屏」和「并行抓两块屏」的耗时差异，并校验并行路径下
每块屏拿到的仍是**原生物理分辨率**（不然裁剪坐标会偏、OCR 精度会掉）。

本机实测（2560x1440@1.5 + 1080x1920@1.0）：

| | 耗时 |
|---|---|
| 串行（v1.2.0 写法） | 1434 ~ 1746 ms |
| **并行（v1.2.1 写法）** | **906 ~ 1227 ms** |
| 并行路径的分辨率 | 两块屏都是原生 ✓ |

> ⚠️ 试过「一次 `getSources` 拿两块屏」，行不通：Chromium 会把第二块屏
> **放大**到 1215x2160（原生是 1080x1920），像素对不上，会伤 OCR 精度。
> 所以只能是「两次调用、并行发」。

### 6.2 带界面的自检（⚠️ 会占用你的桌面）

> **下面这几个脚本会在你当前屏幕上弹出全屏遮罩**，把正在做的事全盖住。
> 先存好手头的活再跑。不影响功能验证的话，用上面 5.0 的无 GUI 版本就够了。

`test_electron.py` 会真的做一遍完整流程：

1. 建一个置顶的已知文本窗口（`Hello 12345 ABCdef` / `识别测试 67890`）；
2. 用 `keybd_event` 模拟 **Ctrl+1**；
3. 用 `SetCursorPos` + `mouse_event` 真的拖一个框；
4. 读回剪贴板，校验 `12345` / `ABCdef` / `识别测试` 都在。


## 8. 修过的 Bug

### 8.1 选区遮罩卡死，Esc 没用（v1.2.1 修复）

**现象**：按 Ctrl+1 之后，屏幕上卡着一个十字光标/压暗遮罩，怎么点都不消失，
按 Esc 也没反应，只能把整个 app 杀掉。

**日志长这样**（连按了 3 次热键）：

```
12:27:01  hotkey pressed
12:27:01  capture start, displays=2
12:27:03  hotkey pressed          ← 上一次抓屏还没结束
12:27:03  capture start, displays=2
12:27:03  captured 2 display(s)
12:27:04  hotkey pressed
12:27:04  captured 2 display(s)
12:27:04  [renderer] overlay: image drawn 1080 x 1920   ← 第 1 套遮罩
12:27:04  [renderer] overlay: image drawn 3840 x 2160
12:27:05  [renderer] overlay: image drawn 3840 x 2160   ← 第 2 套遮罩
12:27:05  [renderer] overlay: image drawn 1080 x 1920
```

**根因**（两层）：

1. **守卫查错了对象。** `startCapture()` 里的守卫是 `if (overlays.size) return;`，
   本意是「已经在选区中就别重复触发」。但**抓屏本身要 2 秒**（双屏各抓一次），
   这 2 秒里 `overlays` 还是空的——遮罩要等抓完才建。
   于是连按热键会**并发跑出多套遮罩**。
2. **Map 装不下多套。** `overlays` 是 `Map<屏幕id, 窗口>`，同一个屏幕 id 只能存一个。
   后建的把先建的挤掉，先建的那套就成了**野窗口**：还盖在屏幕上层、
   还画着十字线，但 `closeOverlays()` 只遍历 `overlays`，再也找不到它 → 关不掉。

**修法**（四层保险）：

| # | 做法 | 作用 |
|---|---|---|
| 1 | `capturing` 标志位，抓屏进行中直接忽略新的触发 | 根因修复：并发根本起不来 |
| 2 | 额外用 `Set` 记下**所有**建过的遮罩窗口，`closeOverlays()` 全量销毁 | 兜底：野窗口也不可能漏网 |
| 3 | 选区期间注册**系统级 `Escape` 全局快捷键**，选完即注销 | 遮罩丢了键盘焦点也能取消 |
| 4 | 每 2 秒自愈扫描：标题为「选区」但不在册的窗口直接销毁 | 最后一道保险 |

顺带加了两个**脱困出口**：

- **选区中再按一次 Ctrl+1** = 取消当前选区并重新抓屏（也能当「换个区域重选」用）；
- **鼠标右键** = 取消（原来右键只是 `preventDefault`，什么也不干）。

另外把抓屏临时图的文件名从 `shot-<屏幕id>.png` 改成 `shot-<token>-<屏幕id>.png`，
并在每次抓屏后清掉不用的旧文件——原来固定文件名，并发时两套遮罩会读到**同一张图**，
其中一套显示的画面还是「旧的」。

**回归测试**（无 GUI 版，见 [§6.0](#60-无-gui-自检默认跑这个不占桌面)）：

```powershell
node test_capture_concurrency.js
```

拿 v1.2.0 的旧源码跑同一套断言，直接复现并证明修复：

| 指标 | v1.2.0（旧） | v1.2.1（新） |
|---|---|---|
| 3 连按触发的 `getSources` 调用 | **6 次**（3 轮 × 2 屏） | **2 次**（每屏一次） |
| 存活遮罩窗口 | **6 个**（Map 里只有 2 个，4 个是野窗口） | **2 个** |
| 系统级 Esc | 无 | 有，且能关干净 |
| 关闭后残留 | **4 个** | 0 |
| 断言结果 | **7 通过 / 9 失败** | **16 通过 / 0 失败** |

> 带界面的 A/B（`test_overlay_ab.py`，会下载旧 exe 跑真程序）也留着，
> 但它会占用桌面，日常用无 GUI 版本就够了。

### 8.2 按了热键之后 1~2 秒没反应（v1.2.2 优化）

**现象**：按 Ctrl+1 之后，屏幕上有将近两秒钟**完全没有反应**。
用户以为没生效，就去连按——这正是 7.1 那个并发 bug 的触发条件。

**根因**：抓屏是**串行**的。双屏要各调一次 `desktopCapturer.getSources()`，
两次加起来 1.4~1.8 秒，而这期间屏幕上什么都看不见。

**修法**：两次调用**并行发**。

| | 耗时 |
|---|---|
| 串行（v1.2.0 / v1.2.1） | 1434 ~ 1746 ms |
| **并行（v1.2.2）** | **906 ~ 1227 ms** |

⚠️ 并行之后**必须校验分辨率没被改**：Chromium 会把缩略图缩放到 `thumbnailSize`，
如果两次调用共用一个尺寸，第二块屏会被**放大**（实测 1080x1920 → 1215x2160），
像素对不上、裁剪坐标会偏、OCR 精度会掉。
所以每块屏仍然单独用**自己的原生物理尺寸**去请求，`bench_capture.js` 会校验这一点。

**关于「抓到一半还在等」时的按键**：抓屏进行中再按热键，那一下会被**直接丢弃**
（日志 `capture ignored`），不排队、不延后。
这不亏——正在跑的那次抓屏结束后本来就会弹出选区界面，
你按的那一下要的正是这个界面，所以是冗余的。

### 8.3 选区界面永远不撤（v1.2.3 修复）

**现象**：按了热键、选区界面弹出来之后，如果用户没接着操作，
这块遮罩会**一直盖在屏幕上**不消失，只能手动按 Esc 或杀进程。

**修法**：给选区加一个**空闲自动取消**计时器（默认 2 秒，可配置）：

- 选区界面 armed 的那一刻开始计时；
- 渲染层把用户的任何动作（挪鼠标、按键、开始拖拽）报给主进程，
  主进程收到就**重新计时**；
- 拖拽过程中渲染层每 400ms 报一次，保证拖到一半不会被收走；
- 超时后自动 `closeOverlays('idle-timeout')`，屏幕恢复正常，
  程序回到「等下一次热键」。

顺带把**抓屏途中再按热键**的语义改掉了：

| | 改之前 | 改之后 |
|---|---|---|
| 抓屏途中按热键 | 直接忽略（这一下白按） | 这次抓完**作废**，立刻重抓（**最新的按键赢**） |

还加了 **250ms 热键防抖**——按住 Ctrl+1 不放时系统会连发，
防抖保证只认「人按了一下」，不会连着重抓。

**回归测试**：`test_capture_concurrency.js` 的第 6/7/8 组断言，
覆盖「超时自动撤」「有动作就重新计时」「抓屏途中再按会重抓」。

### 8.4 「结果窗口不自动关闭」这个设置是坏的（v1.2.4 修复）

设置里有个勾选框「结果窗口不自动关闭」，写进了 `config.json`，
但**代码里从来没人读它**——结果面板永远弹出、也永远不会自动关。
用户以为能选，其实选了没用。

**修法**：换成一个真正生效的三档下拉 **「识别结果显示」**：

- `always` 弹出并保留
- `auto` 弹出，3 秒后自动关（期间点了复制/改文字就不关了）
- `silent` **完全不弹**，文字直接进剪贴板，屏幕上什么都不出现

老配置自动映射，不用手动改：
`keep_result_window=false` → `auto`，`=true` → `always`。

**教训**：设置项要在**真正读它的地方**有断言。
`test_capture_concurrency.js` 的第 9 组断言专门覆盖三档的取值与老配置映射。

### 8.5 双击 exe 会误触发截图（v1.2.6 修复）

**现象**：程序已经在后台跑着，用户又双击了一下 exe 想打开它，
结果屏幕上**突然压上一层选框**，直接进了截图状态。

**根因**：单实例锁把新进程挡掉，转而触发 `second-instance` 事件，
而它的处理写的是：

```js
app.on('second-instance', () => {
  if (settingsWin) { settingsWin.show(); settingsWin.focus(); }
  else startCapture();          // ← 没有设置窗口就直接截图
});
```

用户双击 exe 的本意是「我想打开它」，不是「给我截个图」。

**修法**：`second-instance` 改成只打开设置窗口，**绝不截图**。
顺手把单击托盘图标的行为也改掉（原来也是直接截图）：

```js
tray.on('click', () => { if (tray) tray.popUpContextMenu(); });   // 弹菜单，符合 Windows 惯例
tray.on('double-click', () => openSettings());
```

**回归测试**：`test_capture_concurrency.js` 第 11 组，
断言「再双击 exe 不增加 `getSources` 调用」「点托盘只弹菜单」，
并用 `getSources` 的调用次数做判据（4 → 4，没有增加）。

### 8.6 自检脚本会抢占桌面（v1.2.2 修正）

带界面的自检脚本会在**当前桌面**弹出全屏遮罩，把人正在做的事全盖住，
体验很差。现在：

- 所有 GUI 自检脚本开头都加了**醒目警告**，说明会占用桌面；
- 推荐改跑**无 GUI** 的 `test_capture_concurrency.js`——
  用假的 Electron 加载真实的 `main.js`，半秒跑完 26 项断言，
  **不创建任何窗口、不弹窗**；
- 抓屏延迟基准 `bench_capture.js` 同样不开窗口。
