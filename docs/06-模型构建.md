## 1. 拿 ONNX 权重

用 RapidOCR 自带的 PP-OCRv4 权重（ONNX），这样 CPU 基准和 NPU 用的是
**同一套权重**，比出来的差异才只是推理实现差异。

```
det:  ch_PP-OCRv4_det_infer.onnx
rec:  ch_PP-OCRv4_rec_infer.onnx
cls:  ch_ppocr_mobile_v2.0_cls_infer.onnx
keys: ppocr_keys_v1.txt
```

## 2. 剪掉末尾的 Softmax / Sigmoid

**这一步不能省**，原因见 [02-精度对齐](02-精度对齐.md#坑-1最隐蔽末尾的-softmax-不能留在-npu-上)。

```bash
python strip_tail.py ch_PP-OCRv4_det_infer.onnx ppocr_v4_det_logits.onnx
python strip_tail.py ch_PP-OCRv4_rec_infer.onnx ppocr_v4_rec_logits.onnx
python strip_tail.py ch_ppocr_mobile_v2.0_cls_infer.onnx ppocr_v4_cls_logits.onnx
```

## 3. 编译成 RKNN

`board/conv.py` 是通用转换器：

```bash
CONV_SRC=/opt/npu-ocr/models/ppocr_v4_det_logits.onnx \
CONV_DST=/opt/npu-ocr/models/ppocr_v4_det_ms.rknn \
CONV_DYN_SHAPES=1,3,736,736@1,3,736,992@... \
/opt/rknnconv/bin/python -u conv.py
```

`CONV_DYN_SHAPES` 用 `@` 分隔多个形状，每个都是 `1,3,H,W`。

最终需要的模型：

| 模型 | 形状数 | 说明 |
|---|---|---|
| `ppocr_v4_det_ms.rknn` | 17 个输入尺寸 | 按长宽比吸附到最接近的受支持尺寸 |
| `ppocr_v4_rec_lmw.rknn` | 16 个宽度 | 320, 352, 384, …, 1024 |
| `ppocr_v4_cls_l192.rknn` | 1（192×48） | |
| `ppocr_v4_rec_l320.rknn` | 1（320×48） | 备选 |

多尺寸 det 模型旁边要有同名 `.sizes.json`（支持的形状清单），
**运行时靠它吸附尺寸，不能删**。

## 工具链踩坑清单

### `load_onnx` 不能传 `inputs`

```python
rknn.load_onnx(src, inputs=[...], input_size_list=[...])   # ✗
```

这会走 toolkit 的 crop 路径，生成坏掉的 Conv 节点，ORT 报
`Attribute dilations has incorrect size`。

```python
rknn.load_onnx(src)     # ✓
```

### `dynamic_input` 的形状格式

```python
rknn.config(dynamic_input=True)                       # ✗ "need to be a list of list"
rknn.config(dynamic_input=[[[1,3,48,320]], [[1,3,48,1024]]])   # ✓
```

* 必须是**列表的列表**：每个元素 = 一组输入，每组里是各输入的形状
* **只接受正整数**，不支持 `-1` 全动态
* 不传形状直接 `load_onnx` 会报 `input shape ... not support`

### 2.x 没有这些

```python
from rknn.config import Config        # ✗ 2.x 无此模块
rknn.config(input_size=...)           # ✗ 2.x 不支持
rknn.build(optimization_level=3)     # ✗ 属 config 的参数
```

### ONNX 常量要先折成 Initializer

常量节点要先跑一遍 onnxoptimizer：

```python
onnxoptimizer.extract_constant_to_initializer(onnx_model)
```

否则 toolkit 处理起来容易出问题。

### det 的形状数有上限

工具链内存有限。det 模型编 47 个尺寸 → **OOM kill（rc=-9）**；
19 个尺寸也挂过一次。板上 3.6 G 内存，**17 个是能过的上限**，再多就 OOM。

rec 16 个宽度没问题。

### 精度相关的无效尝试

* `float_dtype='float32'` —— 对 det 精度**无改善**
* `optimization_level=3` —— 同上
* int8 量化 —— 会掉精度，不做

## RKNN 运行时

```python
from rknnlite.api.rknn_lite import RKNNLite

r = RKNNLite(verbose=False)
r.load_rknn(path)
r.init_runtime(core_mask=RKNNLite.NPU_CORE_0)   # 每实例钉一个核
out = r.inference(inputs=[canvas])               # canvas 必须是 4 维 NHWC
```

* 输入必须 4 维 NHWC，rec 的 batch 固定 1
* 多尺寸模型只能取编译时声明过的离散形状
* 运行时噪音用环境变量 `RKNN_LOG_LEVEL=0` 静默
* `W rknn-toolkit-lite2 version: 2.3.2` 那几行是 import 时打的，压不掉，无碍
