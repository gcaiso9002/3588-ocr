# 01 · 项目总览

## 目标

把 PaddleOCR 真正跑在 RK3588 的 NPU 上，并且**识别精度追平 CPU 版**。

CPU 版指 RapidOCR / ONNXRuntime，用的是**同一套 PP-OCRv4 权重**，
所以两边比的是纯粹的推理实现差异，不是模型差异。

## 硬件

| | |
|---|---|
| 板子 | 视美泰 AIoT 3588（`ailot3588`），RK3588，3 核 NPU |
| 系统 | Linux，Python 3.11 |
| 有线 IP | 192.168.31.230（`ssh 3588`） |
| 无线 IP | 192.168.31.40（`ssh 3588-wifi`） |
| 板上工具链 | `rknn-toolkit2` 2.3.2（编译） / `librknnrt.so` 2.2.0（运行时） |

版本不完全匹配（编译用 2.3.2，运行时只有 2.2.0）会有告警，但实测能跑。
pip 上只有 2.3.0 / 2.3.2 / 2.5.0，**没有 2.2.0**，配不上。

## 架构

```
        ┌──────────────────────────────┐
        │  电脑（Windows）              │
        │   3588-ocr (Electron)  Ctrl+1 框选 │
        │   npu_ocr_client.py (命令行)  │
        └───────────┬──────────────────┘
                    │ HTTP POST /ocr (multipart 或 raw body)
                    ▼
        ┌──────────────────────────────┐
        │  板子                          │
        │   npu_ocr_server.py  :8766     │
        │      └─ NpuOcr                 │
        │          ├─ Det   (NPU)        │
        │          ├─ Cls   (NPU)        │
        │          └─ Rec   (NPU × 3 核) │
        └──────────────────────────────┘
```

* 板子上**只有识别**，后处理（DB / CTC）用 numpy 在 CPU 上做——这部分很便宜。
* 模型常驻（systemd `npu-ocr.service`），每次请求只付推理时间，
  不付 ~1.9 s 的冷启动（python 导入 + 加载 3 份 rec 模型）。
* 电脑端的工具是可选的：板子上的服务本身就是一个通用 OCR API。

## 板子上的目录

```
/opt/npu-ocr/
├── npu_ocr.py               流水线（det → cls → rec），NPU 推理 + numpy 后处理
├── npu_ocr_server.py        HTTP 服务（:8766）
├── conv.py                  通用 ONNX → RKNN 转换器
├── strip_tail.py            剪掉模型末尾的 Softmax / Sigmoid
├── build_det_ms.py          构建多尺寸 det 模型
├── compare.py               与 CPU 基准逐行 diff
├── npu-ocr                  CLI 入口（/usr/local/bin/npu-ocr）
├── models/
│   ├── ppocr_v4_det_ms.rknn      det，17 个输入尺寸，输出 logits
│   ├── ppocr_v4_rec_lmw.rknn     rec，16 个宽度，输出 logits
│   ├── ppocr_v4_rec_l320.rknn    rec，单宽度 320（备选）
│   ├── ppocr_v4_cls_l192.rknn    cls，输出 logits
│   ├── ppocr_keys_v1.txt         6623 个 CTC 字符
│   ├── ppocr_v4_det_logits.onnx  ↑ 上面几个模型的 ONNX 源
│   ├── ppocr_v4_rec_logits.onnx
│   ├── ppocr_v4_cls_logits.onnx
│   └── experimental/             被取代的实验版（保留可回退）
├── scratch/                 探针脚本
└── README.md
```

模型目录里 `*.sizes.json` 是多尺寸模型的「支持哪些输入形状」清单，
**不能删**——运行时靠它把输入吸附到最接近的受支持尺寸。

## 环境变量开关

| 变量 | 默认 | 说明 |
|---|---|---|
| `NPU_WORKERS` | 3 | cls+rec 用几个核（1 = 退回单线程） |
| `DET_CORE_MASK` | `0_1_2` | det 图可用哪些核（`0` / `0_1` / `0_1_2` / `auto`） |
| `DET_MODE` | `rapid` | `rapid` = PaddleOCR 几何；`stretch` = 拉满画布（退路） |
| `DET_THRESH` | 0.3 | DB 二值化阈值 |
| `DET_DILATE` | 2 | DB 膨胀核尺寸（PaddleOCR 默认 2×2） |
| `REC_MODEL` / `REC_WIDTHS` | — | 覆盖 rec 模型与它接受的宽度 |
| `REC_MODE` | `auto` | `auto` / `stretch` / `chunk` |
| `MIN_SCORE` | 0.5 | 低于这个置信度的行丢掉 |
| `CLS_THRESH` | 0.9 | cls 分数超过它才旋转 180° |
| `REC_LOGITS` | 1 | rec 模型没有末尾 Softmax（输出 logits） |
